**Purpose:** record current evidence for a Codex-native, provider-portable harness and identify which patterns transfer to ChatGPT Work.

## Evidence conventions

- **Documented:** explicitly stated by an official page, specification, or source file.
- **Observed implementation:** verified in a repository at the exact commit shown.
- **Inference:** a conclusion drawn from multiple documented mechanisms.
- **Recommendation:** the v0 design choice made from the evidence.
- A floating product page or repository branch is not treated as reproducible implementation evidence. Exact commits are recorded for code sources.
- ChatGPT Work product behavior is treated separately in `chatgpt-work-applicability.md`; the last column below records only the direct transfer from each primary source.

## Research-level decision

The primary evidence supports the boundary already proposed in the brief:

```text
Trusted host orchestrator
        |
        +-- Codex App Server adapter
        +-- workspace/worktree manager
        +-- durable state and event store
        +-- deterministic validation
        +-- optional independent evaluator
        +-- budgets, approvals, and recovery
```

The research **does not yet constitute ADR approval or implementation authorization**. The next repository-side step is to merge these findings with Codex’s direct repository/environment inspection and then write `ADR-001-harness-boundary.md`.
